# 修改本人账单确认状态

已开启确认的账本中，参与人可以在账单详情中修改自己的显式决定：已确认改为拒绝，或已拒绝改为确认。创建者、付款人和临时成员显示“无需确认”，不能通过此入口修改自动确认。未回应的参与人仍通过原有确认/拒绝入口作出首次选择；其他人拒绝后，不能靠新的首次选择覆盖整笔账单的拒绝状态。

沿用 `POST /expenses/{expense_id}/confirm`，请求 `status` 为 `confirmed` 或 `rejected`。后端校验当前账本成员、参与资格和账本确认开关，更新当前登录用户的原确认记录，不新增重复记录，也不修改其他人的记录。修改入口也允许对已全员确认的账单重新拒绝。

账单整体状态每次重算：存在任何必需参与人的拒绝则为已拒绝；所有必需参与人均确认则为已确认；否则为待确认。账单行锁用于串行化同一账单的回应。每次有效修改仍写入审计并通知创建者。

iOS 成员行中的本人状态可展开，提供切换到另一状态的操作；提交期间禁用，失败保留原状态并在本人行显示错误。修改成功后刷新账单状态和转账流向。成员状态区使用统一列宽，图标独立占列；每两名成员间显式显示分隔线。

账单修改会改变转账流向的支出输入，已记录的转账历史保留。当前系统的转账历史记录不关联单张账单，也不从建议流向中扣除；本次修改没有增加自动撤销支付或冲销转账的逻辑。

需要更新后端与 iOS 客户端，没有新增数据库迁移。
