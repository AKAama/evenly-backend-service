# 账单图片凭据

图片凭据为可选项，每张账单最多 3 张。沿用头像、封面使用的腾讯 COS 服务和现有 bucket，对象前缀为 `receipts/{ledger_id}/{user_id}/`，文件名由存储服务生成 UUID。`recipe` 是“食谱”；凭据使用 `receipt`。

## 上线顺序

先在后端环境执行 `alembic upgrade head`，增加 `expenses.receipt_urls` JSON 列，再部署后端，最后发布 iOS 客户端。本次新增迁移为 `20261007_0026`，旧账单默认为空数组。无需新建 bucket 或实体目录，也没有新增存储配置。

## 接口

- `POST /expenses/ledgers/{ledger_id}/expenses/with-receipts`：新建账单并上传图片。
- `PUT /expenses/{expense_id}/with-receipts`：编辑账单，保留或移除已有图片，并上传新图片。

接口使用 `multipart/form-data`，`payload` 为原有账单请求的 JSON 字符串，重复的 `files` 字段为新图片；`payload.receipt_urls` 为要保留的图片地址。已有图片和新图片合计最多 3 张。编辑仍受原有创建者和账单状态权限限制。

后端限制单图 5MB，检查 JPEG、PNG、GIF、WebP 的 MIME 类型与文件头，拒绝来自其他账本或用户目录的新地址。iOS 在本地按原比例处理为最长边 1600 像素的 JPEG，不裁剪凭据；点击保存才上传。上传失败保留表单，用户可重试或移除图片后保存。

无新图片时继续使用原 JSON 接口。旧客户端编辑请求若未包含 `receipt_urls`，保留已有凭据；显式传空数组表示移除所有凭据。列表和详情响应均包含 `receipt_urls`。

上传中断或保存失败时会尝试清理新上传且未被账单引用的对象。编辑移除凭据或删除账单后，会尝试清理无引用图片；清理失败记日志，不影响已经完成的账单操作。账本整体删除沿用原有逻辑，此功能没有增加整本删除时的对象清理。

## 存储可见性

凭据图片从 `GET /expenses/{expense_id}/receipts/download-url?receipt_url=...` 获取临时下载地址。接口验证登录用户为账本成员，且指定图片确实属于该账单，再生成 COS 直连地址的 GET 签名，有效期 15 分钟，响应禁止缓存。数据库与客户端账单缓存仍保存原始对象地址，缩略图、编辑页已有凭据和大图预览每次加载时获取新签名，避免过期地址被持久保存。

现有 COS bucket 为私有访问，凭据读取不依赖自定义 CDN 域名的证书，也无需把图片改为公共读取。此前已经上传的凭据可直接使用，不需要重新上传。头像、封面的访问逻辑未调整。上线此修复需同时更新后端下载地址接口与 iOS；没有新增数据库迁移。
